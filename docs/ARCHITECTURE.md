# Architecture: Realtime WebRTC Voice Agent

## System Diagram

```mermaid
sequenceDiagram
    participant User
    participant Browser
    participant FastAPI
    participant OpenAI

    User->>Browser: Opens App
    Browser->>FastAPI: POST /api/realtime/session
    FastAPI->>OpenAI: POST /v1/realtime/sessions (with API_KEY)
    OpenAI-->>FastAPI: Ephemeral Token
    FastAPI-->>Browser: Ephemeral Token

    Note over Browser,OpenAI: WebRTC Handshake
    Browser->>OpenAI: SDP Offer (Bearer: Ephemeral Token)
    OpenAI-->>Browser: SDP Answer

    Note over User,OpenAI: True Realtime Audio Streaming
    User->>Browser: Speaks
    Browser->>OpenAI: Audio Stream (WebRTC Track)
    OpenAI-->>Browser: Audio Stream (WebRTC Track)
    Browser->>User: Audio Playback

    Note over Browser,OpenAI: Tool Calling (RAG)
    OpenAI->>Browser: DataChannel: function_call(retrieve_company_knowledge)
    Browser->>FastAPI: POST /api/tools/execute
    FastAPI->>FastAPI: Query ChromaDB Vector Store
    FastAPI-->>Browser: Context Results
    Browser->>OpenAI: DataChannel: function_call_output
    OpenAI-->>Browser: Synthesized response based on context
```

## Why Ephemeral Tokens?
Connecting directly to OpenAI's WebRTC endpoints requires an API Key. If we put our standard `OPENAI_API_KEY` in the browser, any user could steal it.
The Ephemeral Token is a temporary credential generated by our backend. It dictates exact restrictions (voice, system prompt, allowed tools) and expires quickly. 

## VAD (Voice Activity Detection)
We utilize OpenAI's `server_vad` configuration. When the AI is speaking and the user interrupts, OpenAI's edge servers immediately detect the human voice, halt the TTS generation, and send a `response.cancel` event down the WebRTC data channel. The frontend does not need manual volume thresholds.
